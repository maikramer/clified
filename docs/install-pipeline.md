# Install pipeline

This document traces a tool installation from the CLI through to the receipt on
disk. Module names refer to `clified.installer.*`.

## Entry points

```
python -m clified
       │
       ├── known subcommand (list, get, install, …)  → cli.main → _cmd_*
       │
       └── legacy argv (tool name, --get, --list)     → unified.main

clified-install  →  unified.main  (always)
```

Both paths converge on `install_tool()` / `install_all()` in `unified.py`.

## High-level flow

```
load_registry()          ← tools.yaml → WorkspaceConfig + ToolSpec map
       │
get_tool(name)           ← resolve key, install_before, cross_deps
       │
pick installer           ← PythonProjectInstaller | Rust | Bun
       │
_run_with_retry(action, installer.run)
       │
       ├── install / update / reinstall
       └── uninstall → run_uninstall()
       │
record_install()         ← if success and receipt_ctx provided
```

## Registry loading

`registry.load_registry()`:

1. Read YAML from `clified.paths.tools_yaml_path()`
2. Parse `workspace` section → `WorkspaceConfig(root, name, shared_python)`
3. Parse each `tools.*` entry → `ToolSpec` (kind, folder, hooks, bounds, …)
4. Invalid tool entries raise `ValueError` with the tool key in the message

After `--get`, `CLIFIED_TOOLS` points at the cloned repo's YAML and
`registry.reset_registry()` clears any cached parse.

## `install_tool()` details

### Installer selection

| `kind` | Class | Key paths |
|--------|-------|-----------|
| `python` | `_ToolPythonInstaller` | `project_root/.venv`, pip/uv |
| `rust` | `_ToolRustInstaller` | `target/release/<bin>` |
| `bun` | `BunProjectInstaller` | `node_modules`, bun script |

### Actions

| Action | Installer method | Receipt |
|--------|------------------|---------|
| `install` | `run()` | Written on success |
| `update` | `run()` with `UV_VENV_CLEAR=0` | Updated |
| `reinstall` | `run_reinstall()` | Updated |
| `uninstall` | `run_uninstall()` | Removed on success |

`UV_VENV_CLEAR` is saved and restored around update — prevents leaking
`UV_VENV_CLEAR=0` into subsequent installs in the same process.

### Retry wrapper

`_run_with_retry(action, func, logger, max_attempts)`:

- `max_attempts=1` by default; `CLIFIED_RETRY=1` or `--retry N` enables retries
- Uses `RetryEngine` with exponential backoff
- **Permanent failures:** `FileNotFoundError`, `PermissionError`, installer
  returning `False` — never retried, never masked as success
- On final failure, `_diagnose_failure()` may suggest fixes from pattern DB

## Python install sequence

`PythonProjectInstaller.run()` (simplified):

```
1. check_python_version(min_python, max_python)
2. install_system_dependencies()     ← optional OS packages
3. ensure_project_venv()
      ├── uv venv (preferred) or python -m venv
      ├── verify ABI against max_python
      └── install shared_python (editable) if configured
4. install_in_venv()
      ├── custom_install hook  OR
      ├── pip install -e . / requirements.txt
      ├── patch relative file: deps in pyproject.toml (uv compatibility)
      ├── link cross_deps via .pth
      └── optional PyTorch / nvdiffrast (needs_pytorch, hooks)
5. create_cli_wrappers()
      ├── main cli_name wrapper
      └── extra_aliases
6. post_install hook
7. create_activate_wrapper()         ← optional shell helper
8. ensure PATH contains bin_dir
```

### Relative `file:` dependencies

Monorepos often declare:

```toml
dependencies = ["aigamekit-shared @ file:../Shared"]
```

Before `uv pip install`, Clified temporarily rewrites these to absolute
`file:///…` URLs (forward slashes) because uv rejects malformed Windows paths.
Original line endings in `pyproject.toml` are preserved.

### Cross-dependencies

`cross_deps: [text2d]` adds `.pth` files in the venv pointing at sibling
tools' `src/` trees — without pip-installing them as separate packages.

`install_before` ensures dependency tools are prepared first (venv + `.pth`
only when `install_before_mode: venv_only`).

### Wrappers

Generated by `write_cli_wrapper()` in `base.py`:

**Unix** (`~/.local/bin/denv`):

```bash
#!/usr/bin/env bash
# DENV — gerado por clified
exec "/path/to/.venv/bin/python" -m denv "$@"
```

**Windows** (`denv.cmd`):

```batch
@echo off
REM DENV — gerado por clified
"/path/to/.venv/Scripts/python.exe" -m denv %*
```

The marker `gerado por clified` identifies Clified-owned wrappers for `doctor`.

### Site-packages discovery

`_find_site_packages(venv_dir)` checks:

- `lib/pythonX.Y/site-packages` (Unix layout)
- `Lib/site-packages` (Windows venv layout)

## Rust install sequence

```
1. cargo build --release  (if binary missing or --force)
2. copy target/release/<cargo_bin_name> → INSTALL_PREFIX/bin/<cli_name>
3. ensure PATH
4. test_installation (--version smoke test)
5. post_install hook (optional)
```

## Bun install sequence

```
1. bun install [--frozen-lockfile]
2. bun run <bun_build_command>  (optional)
3. write wrapper → bun run <bun_cli_script>
4. test_installation
```

On Windows, smoke tests invoke `.cmd` wrappers via `cmd /c`.

## Hooks

Executed by `_run_hook()` / `_run_post_install()`:

1. Parse `module:function` from `tools.yaml`
2. Insert `project_root` (and shared package src) on `sys.path`
3. Import and call `func(installer)`
4. `False` return aborts the install

See [Hooks](hooks.md) for built-in and local hooks.

## `install_all()`

Used by `clified-install all` and catalog entries with `tool: all`:

1. Topological sort by `install_order` and `install_before`
2. For each tool: `install_tool()` with shared `receipt_ctx_factory`
3. Results keyed by **`spec.key`** (not display name)
4. Returns `(all_ok, list[InstallResult])`

## Receipt construction

On success, `_build_receipt()` collects:

- Installer paths (`venv_dir`, `project_root`, `bin_dir`)
- Wrapper paths from `create_cli_wrappers()`
- Context from `ReceiptContext` (repo, ref, commit, source, catalog_name)

Written via `record_install(receipt_key, receipt)`.

## Uninstall

`run_uninstall()`:

1. Remove wrappers listed in receipt `artifacts` (or derived from `cli_name`)
2. Optionally remove venv (Python) — controlled by installer logic
3. Does **not** remove git clone (use `clified uninstall --purge`)

Receipt removal happens in `install_tool()` only after `run_uninstall()`
returns `True`.

## JSON output

When `--json` is set, subcommands use `OutputFormatter`:

```json
{
  "status": "success",
  "title": "install",
  "data": { "ok": true, "results": […] }
}
```

Errors use `"status": "error"` with a `message` field — no Python tracebacks
in JSON mode.

## Debugging

```bash
clified install my-tool -v
CLIFIED_RETRY=1 clified-install my-tool --verbose
```

Hook failures: `Hook failed (module:func): …`

Install action failures trigger pattern-based diagnosis when available.
